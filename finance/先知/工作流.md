# 先知消息处理工作流

本文件是处理“先知”小圈消息的正式工作流。收到用户粘贴的新消息后，按本流程完成 **总结、分析、归档、跟踪、校验**，减少反复沟通，并保证历史复盘可以持续接续。

执行本工作流时，必须同时读取并遵守 `finance/先知/README.md` 中的研究方法论、泊松过程、常见主题分类、作者提示词解释和交易手册。本文件只维护执行步骤，不重复维护研究与交易规则。

## 使用入口

当用户输入出现以下任一情况，应自动进入本工作流：

- 出现 **“机构小秘圈”**、**“机构小密圈”**、**“先知”**、**“小秘圈”** 等关键词。
- 出现“群主”“机构小秘圈的聊天室”“自定义”等聊天导出格式。
- 用户要求对相关投研/群聊内容做 **“总结”**、**“分析”**、**“跟踪”**、**“复盘”**、**“整理”**。

每次处理新消息前，优先读取：

1. `finance/先知/工作流.md`
2. `finance/先知/README.md`
3. `finance/先知/主题索引.md`
4. `finance/先知/验证清单.md`
5. `finance/先知/跟踪台账.csv` 的最近记录

## 语言与原则

- 始终使用 **简体中文**。
- 语气专业、理性、客观。
- 日总结的宗旨是**方便人类阅读、条理清晰地整理当天核心内容**，重点是把当天文字消息和图片 OCR 后的文字统一整理成清楚的复盘。
- 日总结正文优先呈现：当天说了什么、核心观点是什么、哪些方向和标的被提到、交易或风险表达是什么。
- 内部处理时仍需区分事实、观点、传闻、截图和作者提示；图片 OCR 后的文字在日总结正文中按普通消息处理，不单独标注图片来源，也不要用通用免责声明冲淡正文。
- 涉及订单、客户、收入、利润、产能、股权、政策、CAPEX、股价、市值目标等内容，在台账或历史关注清单中保留原文关注点和交易表达，日总结正文中只在具体语境下自然说明。
- 钉钉日总结默认不做联网搜索或外部核验；默认读取 `exports/YYYY-MM-DD/先知/messages.md`，并识别 `exports/YYYY-MM-DD/先知/images/` 中的图片、截图和图表，OCR 后作为普通文字消息纳入当天内容。
- 用户明确要求“核验”“联网查证”“查公告”时，再使用公司公告、财报、交易所互动、投资者关系记录、招投标、项目备案、权威媒体或行业权威资料，并遵守本文件的核验与写入边界。

### 日总结输出禁用项

日总结正文中不要出现以下通用提示或同义改写：

- “圈内内容未做外部核验，只作为研究线索和交易复盘线索处理。”
- “截图信息不能直接当作事实。”
- “未联网核验，均按研究线索处理。”
- “不作为事实结论。”
- “需权威来源核验。”

如消息包含具体公告、订单、业绩或价格信息，保留其原文出处和作者提示，不把作者观点改写成确定事实或买卖指令。

## 聊天导出格式识别与脱敏规则

当用户粘贴“机构小秘圈”聊天导出文本时，先识别消息结构，再进行总结、分析、归档或格式整理。若用户明确要求“只格式化”“只梳理格式”，则只做结构识别、换行、分段和脱敏，不总结、不改写正文内容。

1. **作者/群主识别**
   - “机构小秘圈:”表示作者/群主发言。
   - 凡是以“机构小秘圈:”开头的内容，均视为作者回复或作者发言。

2. **成员/学员识别**
   - 除“机构小秘圈:”以外，其他形如“网名:正文”的内容，通常视为成员/学员发言。
   - 从“网名:”之后开始，直到下一条时间、下一个“自定义:”、下一条“机构小秘圈:”、或下一个明显分隔符之前，均视为该成员的一整段发言。

3. **系统标签识别**
   - “自定义:”通常是系统导出标签，不属于正文内容。
   - 如果“自定义:”下一行是“机构小秘圈:”，则说明后面是一条作者消息。
   - 每出现一次“自定义: + 机构小秘圈:正文”，通常视为一条独立的作者消息；连续出现时也应拆成多条作者消息，不合并为一条。

4. **分隔符与时间识别**
   - “-----”、单独的“-”、单独的“•”通常是结构分隔符，不属于正文内容。
   - 分隔符后面通常依次是：时间行、成员网名和成员正文。
   - 形如“2026-05-28 14:52:15”的内容是成员/学员消息时间。

5. **作者回复范围**
   - 从“机构小秘圈:”之后开始，直到下一个“自定义:”、成员时间行、明显分隔符，或下一条发言人标识之前，均视为作者的一整段发言。
   - 若结构为“自定义: + 机构小秘圈:作者内容 + 分隔符 + 时间 + 网名:成员内容”，则前面的“机构小秘圈:作者内容”是作者回复，后面的“时间 + 网名:成员内容”是对应成员消息。

6. **成员昵称脱敏**
   - 对包含明显数字 ID、手机号式长数字、随机编号的成员昵称，应做模糊化处理。
   - 若无法判断是否为真实姓名，保留结构但弱化身份，可写为“成员A”“成员B”。
   - 脱敏只处理昵称或 ID，不改写成员发言正文。

7. **格式整理边界**
   - 保留原文顺序。
   - 保留原文内容。
   - 不总结。
   - 不改写。
   - 不补充解释。
   - 只通过换行、分段、标注“作者/成员/时间”等方式提升可读性。

## 目录结构

原始导出目录：

`exports/YYYY-MM-DD/先知/messages.md` 和 `exports/YYYY-MM-DD/先知/images/`

`exports/` 是钉钉原始导出层，保留原始 Markdown 和图片，不在 `finance/先知/` 下重复建立 raw 或 processed 目录。

研究工作目录：

`finance/先知/`

核心文件与目录：

| 文件或目录 | 用途 |
| --- | --- |
| `README.md` | 总方法论、交易手册、复盘规则 |
| `工作流.md` | 当前文件，定义消息处理、归档、跟踪和提示词整理流程 |
| `reviews/daily/` | 单日主题复盘，文件名为 `YYYY-MM-DD_主题复盘.md` |
| `reviews/weekly/` | 周度、月度或阶段性复盘，文件名为 `YYYY-MM-DD至YYYY-MM-DD_阶段复盘.md` 或 `YYYY-MM_月度合并复盘.md` |
| `reviews/articles/` | 公众号文章复盘，文件名为 `YYYY-MM-DD_文章标题复盘.md`，不保存公众号原文 |
| `topics/` | 长期主题沉淀，如国产算力、AIDC、半导体零部件 |
| `主题索引.md` | 按主题检索相关文件和标的 |
| `跟踪台账.csv` | 按标的持续跟踪作者提示、催化、风险和交易表达 |
| `验证清单.md` | 历史关注清单；文件名仅为兼容现有引用而保留，不记录核验状态 |
| `模板_单条消息复盘.md` | 单条消息复盘模板 |

## 输入处理流程

收到用户粘贴的新消息后，按顺序执行：

1. **读取本地上下文**
   - 先读 `工作流.md`、`README.md`、`主题索引.md`、`验证清单.md`（历史关注清单）。
   - 使用 `rg` 搜索新消息中的核心标的、主题、关键词，确认是否已有历史复盘。
   - 查看 `跟踪台账.csv` 最近记录，避免重复新增同一逻辑。

2. **判断消息类型**
   - 单家公司更新
   - 行业主线更新
   - 宏观/政策/事件扰动
   - 调研纪要/电话会议
   - 公众号长文
   - 交易方法论
   - 用户经验/复盘心得
   - 多主题批量消息

3. **读取钉钉日总结原文**
   - 钉钉导出按日归档，优先读取 `exports/YYYY-MM-DD/先知/messages.md`。
   - 同步检查 `exports/YYYY-MM-DD/先知/images/`；对图片、截图或图表做 OCR/视觉识别，识别出的文字按普通消息合并到当天消息汇总。
   - OCR 后的图片文字只作为输入材料参与整理；最终日总结正文不需要说明“来自图片”“来自截图”，也不单独展示图片清单或图片阅读过程。

4. **识别时间范围与时效性**
   - 判断消息对应日期或时间段。
   - 涉及最新公告、新闻、订单、价格、政策、CAPEX、财报、股价、市值、出口数据等，统一视为 **有时效性**。
   - 钉钉日总结阶段不主动把作者观点改写成事实或评级，正文以整理当天消息核心内容和作者提示为主。
   - 对具体事实只保留原文出处、关注点和交易表达，不另设作者观点验证状态。
   - 公众号 PDF 或长文中出现的图片、截图、图表、标注、表格，按公众号 PDF/长文阅读规则处理。

5. **提取核心信息**
   - 日期或时间范围
   - 来源
   - 主题
   - 涉及行业
   - 涉及标的
   - 作者核心观点
   - 催化因素
   - 业绩或订单数据
   - 交易纪律、情绪表达或风险表达
   - 是否属于低位逻辑、业绩兑现、高位趋势、短期情绪或事件催化

6. **拆成三层逻辑**
   - **行业逻辑**：产业趋势、政策方向、供需格局、景气度。
   - **公司逻辑**：客户、订单、产能、产品、商业模式、利润路径。
   - **交易逻辑**：位置、涨幅、先手优势、量价、5/10 日线、事件情绪。

7. **确定跟踪优先级**
   - 高：国产算力、昇腾链、先进制程、先进封测、测试链、AIDC、Token 工厂等强主线。
   - 中高：半导体设备零部件、光通信、液冷、连接器、核心材料。
   - 中：户储、软件映射、光伏设备等阶段性窗口。
   - 低到中：纯传闻、情绪映射和仅有提示词的概念。

8. **决定归档方式**
   - 单一公司或单一主题：新建 `finance/先知/reviews/daily/YYYY-MM-DD_主题复盘.md`。
   - 公众号长文复盘：新建 `finance/先知/reviews/articles/YYYY-MM-DD_文章标题复盘.md`。
   - 多主题批量消息、周度或阶段性总结：新建 `finance/先知/reviews/weekly/YYYY-MM-DD至YYYY-MM-DD_阶段复盘.md`。
   - 月度总结：新建或更新 `finance/先知/reviews/weekly/YYYY-MM_月度合并复盘.md`。
   - 跨多日、跨月反复出现的长期主线：在月度合并复盘完成后，再更新 `finance/先知/topics/主题名.md`。
   - 若是已有主题的延续：优先在新阶段文件中承接历史文件，不覆盖旧复盘。

9. **每日阶段的更新边界**
   - 每日消息总结只生成或更新 `reviews/daily/`、`跟踪台账.csv` 和按需更新的历史关注清单 `验证清单.md`。
   - 每日阶段不更新 `主题索引.md`，也不强制更新 `topics/`，避免主题索引被单日文件污染，避免主题文件变成流水账。
   - 单日复盘需要检索时，使用 `rg` 在 `finance/先知/reviews/daily/`、`finance/先知/reviews/articles/`、`finance/先知/reviews/weekly/` 和 `exports/` 中搜索主题或标的。

10. **月度阶段的沉淀动作**
   - 月度合并复盘完成后，根据月报更新 `topics/` 中的长期主题文件。
   - 月度合并复盘完成后，再更新 `主题索引.md`。
   - `主题索引.md` 的相关文件只维护到月度合并复盘，显示为相关月份，例如 `2026-03`、`2026-04`。

## 输出文件规则

### 1. 新建复盘文件

单条消息：

`finance/先知/reviews/daily/YYYY-MM-DD_主题复盘.md`

批量消息：

`finance/先知/reviews/weekly/YYYY-MM-DD至YYYY-MM-DD_阶段复盘.md`

公众号文章：

`finance/先知/reviews/articles/YYYY-MM-DD_文章标题复盘.md`

若用户提供公众号 PDF：

- PDF 只作为当次处理输入，不在仓库中长期保存。
- 处理过程中应临时提取文字，并临时逐页渲染为图片进行视觉阅读。
- 处理完成后只保留复盘正文：`finance/先知/reviews/articles/YYYY-MM-DD_文章标题复盘.md`。

推荐结构：

```markdown
# 日期 主题复盘

## 基本信息

- 日期：
- 主题：
- 涉及行业：

## 一句话结论

## 核心观点

## 主题主线拆解

## 重点公司复盘

## 交易与风险表达
```

批量消息推荐增加：

```markdown
## 主线一：主题

### 行业逻辑

### 公司逻辑

### 交易逻辑

## 本批重点跟踪表
```

写作限制：

- 日总结和文章复盘正文中不要生成独立的验证状态或处理结论章节。
- `## 基本信息` 中不要写 `当前状态`、`本次处理边界`。
- 日总结正文中不要生成独立的 `## 内容整理` 或 `## 图片信息阅读` 章节；图片 OCR 文字应合并进相关主题和标的段落，按普通文字消息呈现。
- 如当天消息里有明确交易纪律或风险表达，可使用 `## 交易与风险表达`；不要为了免责声明而强行生成风险章节。
- 需要保留的信息，按作者提示词与交易表达写入历史关注清单；日总结正文只保留与理解核心内容有关的简洁表述。
- 不要在日总结正文中写“未联网核验”“研究线索”“截图不能当事实”“需权威来源核验”等通用提示。

### 2. 更新 `跟踪台账.csv`

新增或更新涉及标的。字段必须保持一致：

```csv
日期,主题,标的,方向,原文定位,关键催化,参考材料,当前位置判断,交易表达,风险点,交易提示,下次复盘日期,备注
```

填写要求：

- `交易提示` 使用作者提示词对应的交易表达，不填写验证状态。
- `参考材料` 保留公告、财报、订单、客户、价格或其他原文出处，仅作背景记录。
- `交易表达` 保留作者原话，可使用：
  - 低位多看逻辑
  - 高位多看图；趋势保持留
  - 提示机会；观察催化
  - 趋势破位走；止盈止损
  - 交易纪律和风险表达
- `交易提示` 使用统一表达：
  - 低位关注产业逻辑和基本面
  - 趋势未破时跟踪量价
  - 提示机会，观察事件催化
  - 条件式退出或利润保护
  - 交易纪律和风险表达
- 已经涨幅较大的标的，必须在风险点中写入 **估值提前反映、高位回撤、趋势破位风险** 等。
- 对同一标的的新逻辑，可以新增一行；对完全相同逻辑，优先更新原有行的备注和交易提示，避免重复堆叠。

### 3. 更新 `topics/`

`topics/` 是长期主题沉淀层，不是每日流水记录。

更新时机：

- 月度合并复盘完成后。
- 某条主线跨多日、跨月持续出现，已经从单日消息变成长期跟踪主题。
- 主题逻辑、重点标的、验证问题或风险反证发生明显变化。

推荐结构：

```markdown
# 主题名称

## 主题定位

## 月度复盘摘要

## 核心逻辑链

## 重点方向与标的

## 关键关注问题

## 风险提示

## 相关月度复盘

| 月份 | 文件 |
| --- | --- |

## 后续更新记录
```

### 4. 更新 `主题索引.md`

`主题索引.md` 是月度级检索入口，只在月度合并复盘完成后更新。

维护规则：

- `相关月份` 只填写月份，例如 `2026-03`、`2026-04`。
- 链接只指向 `finance/先知/reviews/weekly/YYYY-MM_月度合并复盘.md`。
- 不再逐篇索引 `reviews/daily/` 下的单日复盘。
- 不再逐篇索引单条长文或原始导出。
- 单篇检索统一使用 `rg` 搜索主题、标的或关键词。

新增主题索引示例：

```markdown
## 新主题名称

| 子主题 | 相关月份 | 相关标的 |
| --- | --- | --- |
|  | [2026-03](reviews/weekly/2026-03_月度合并复盘.md) |  |
```

### 5. 更新历史关注清单

历史关注清单的文件名仍为 `验证清单.md`，仅为兼容现有引用而保留。该文件只记录原始关注点、参考材料、作者提示词和交易表达，不设置“已验证、部分验证、未验证”等状态。

### 6. 核验与写入边界

钉钉日总结默认不联网搜索，正文以整理当天核心内容和作者提示为主。用户明确要求核验时，按以下规则执行：

- 用户只要求核验、没有要求写入时，核验结果只在当次回复中呈现。
- 用户要求写入并指定位置时，按用户指定位置更新。
- 用户要求写入但没有指定位置时，更新与该消息或主题对应的现有复盘文件。
- 找不到对应的现有复盘文件时，必须先询问用户写入位置，不得擅自新建文件。
- 核验结果不写入 `验证清单.md`，也不在 `跟踪台账.csv` 中新增核验状态字段。
- 核验结果不得改写作者原始提示词和交易表达。

## 公众号 PDF/长文阅读规则

当用户提供公众号 PDF、公众号截图、图文长文，或明确说“公众号文章”“PDF”“图文并茂”“图片里有信息”时，必须执行本节规则。

### 1. 输入来源处理

| 输入形式 | 处理方式 |
| --- | --- |
| 用户直接粘贴全文 | 直接生成 `reviews/articles/YYYY-MM-DD_文章标题复盘.md`，不额外保存原文 |
| 用户提供 PDF | PDF 只作为当次输入；临时抽取文本并逐页渲染阅读，处理后不保留 PDF 或页面图片 |
| 用户提供截图 | 将截图作为页面证据阅读，复盘中说明可识别程度 |

### 2. PDF 阅读强制步骤

处理 PDF 时，不得只抽取文字。必须按顺序执行：

1. **确认页数**：记录 PDF 总页数。
2. **抽取文本**：提取可复制正文，作为文字线索。
3. **临时逐页渲染**：把每页 PDF 临时渲染成图片用于阅读，不把页面图片写入仓库。
4. **逐页阅读图片**：识别页面中的图表、截图、标注、图片文字、表格和版式关系。
5. **图文对照**：说明图片或图表如何支撑、补充或削弱正文观点。
6. **完整性校验**：确认每页都已阅读，不能跳过“看起来只是图片”的页面。
7. **不确定性标注**：低清、遮挡、截断、无法识别的图片内容，必须写明“未能可靠识别”，不能硬猜。

### 3. 逐页笔记要求

处理 PDF 后，复盘文件中必须包含“完整性检查”和“图文证据拆解”。如果文章没有图片或图表，也要写明“未发现独立图表页”。

推荐写法：

```markdown
## 完整性检查

- PDF 页数：
- 已阅读页数：
- 是否完成逐页视觉阅读：
- 图片/图表页：
- 无法可靠识别内容：

## 图文证据拆解

| 页码 | 图/表/截图内容 | 对应文字观点 | 复盘理解 | 关注问题 |
| --- | --- | --- | --- | --- |
```

### 4. 文章复盘边界

- 公众号复盘是 **文章观点复盘**，不是原文转载。
- 复盘应提炼观点、逻辑链、证据、标的、风险和作者提示。
- 不逐字复制长篇原文。
- 不把文章观点写成事实。
- 若文章包含公司订单、客户、业绩、价格、政策等时效性信息，在历史关注清单中保留原始关注点和参考材料。
- 若文章观点与钉钉消息、月度复盘或主题文件相关，应在月度合并时统一纳入，不逐篇写入 `主题索引.md`。

### 行业主线判断

优先分析：

1. 政策是否支持
2. 产业趋势是否明确
3. 需求是否持续放大
4. 供给是否存在瓶颈
5. 是否有订单、财报或 CAPEX 验证
6. 是否处于市场主线
7. 是否已有过度交易
8. 是否已有历史提示和先手优势
9. 是否由单点催化升级为产业趋势或业绩兑现
10. 是否存在 **λ 上升**：关键事件强度、证据密度和状态跳变概率是否正在提高

### 公司分析

每家公司至少拆解：

| 维度 | 说明 |
| --- | --- |
| 原文定位 | 作者如何定义这家公司 |
| 核心逻辑 | 行业、客户、订单、产能、产品、模式 |
| 催化 | 财报、订单、调研、政策、客户、价格、产能 |
| 事件强度 λ | 未来 1-2 个季度关键事件出现的强度，如财报、订单、招标、客户认证、价格变化、产品发布 |
| 证据网络 | 客户、订单、收入、利润率、产能、价格、产业趋势、量价行为等原文信息 |
| 等待质量 | 作者提示是低位关注逻辑、观察催化，还是高位跟踪量价 |
| 退出条件 | 原文是否出现趋势破位、止盈止损或利润保护表达 |
| 作者提示 | 原文提示词及其交易表达 |
| 风险 | 高位、估值、客户集中、订单不确定、兑现慢 |

### 交易判断

交易判断必须读取并遵守 `finance/先知/README.md` 中的研究方法论、泊松过程与交易手册，不在本工作流重复维护仓位、趋势线、等待和退出规则。

### 事实与观点分层

复盘文件中应明确区分：

| 类型 | 写法 |
| --- | --- |
| 已公开验证 | “公告显示”“官方资料显示”“权威媒体报道” |
| 圈内观点 | “原文称”“作者认为”“圈内逻辑为” |
| 产业链传闻 | “据产业链转述”，不改写成确定事实 |
| 交易判断 | “短期按事件驱动跟踪”“高位看趋势量价” |
| 风险提示 | “若订单/价格/份额不及预期，逻辑需下修” |

## 写作要求

- 第一句话直接给核心结论。
- 多主题内容优先用表格。
- 步骤和流程用有序列表。
- 重点结论、风险、规则用 **加粗**。
- 不做投资建议，不写“买入”“卖出”作为直接指令。
- 用作者原文中的“低位多看逻辑”“高位多看图”“趋势破位走”“止盈止损”等交易表达。
- 对圈内观点使用“原文称”“作者认为”“圈内逻辑为”，不追加验证状态标签。
- 不把市值目标、利润测算、客户份额写成确定事实。

## 完成后的检查

每次处理完用户消息后，必须检查：

1. 是否新建了复盘文件。
2. 是否更新了 `跟踪台账.csv`。
3. 当前是否为月度合并阶段；只有月度合并完成后才允许更新 `主题索引.md` 和 `topics/`。
4. 是否需要更新历史关注清单 `验证清单.md`。
5. 是否保留了作者原文提示词和交易表达。
6. 是否套用了交易手册约束。
7. 是否用 `rg` 校验新文件、核心关键词、索引和历史关注清单能互相命中。
8. 是否用字段检查确认 `跟踪台账.csv` 每行仍为 13 个字段。
9. 若处理公众号 PDF，是否完成页数、逐页图片、图文证据和无法识别内容检查。
10. 是否在最终回复中列出新增或更新的文件名或变更项，不展示存储位置。

推荐校验命令：

```bash
rg -n "核心关键词|新增文件名" finance/先知
wc -l finance/先知/reviews/daily/新增文件.md finance/先知/跟踪台账.csv finance/先知/主题索引.md finance/先知/验证清单.md
awk -F, 'NF!=13 {print NR ":" NF ":" $0}' finance/先知/跟踪台账.csv
```
