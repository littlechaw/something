# 其他博主公众号汇总工作流

本文件用于生成、更新或整理 `finance/其他博主汇总/reviews/articles/YYYY-MM-DD_其他博主公众号汇总.md`。处理前必须识别用户是要求原文汇总，还是要求先总结后归档，并按对应分支写入。

## 触发条件

- 用户提到“其他博主公众号汇总”“其他博主汇总”“每日公众号汇总”等同类内容。
- 用户要求生成、更新或整理 `finance/其他博主汇总/reviews/articles/YYYY-MM-DD_其他博主公众号汇总.md`。
- 用户粘贴多位博主、公众号作者或文章片段，并明确要求放入每日汇总。

## 意图识别与处理分支

### 原文汇总

当用户表达“汇总今日其他博主”“归档今日其他博主”，并提供“作者 + 内容”时，默认视为原文汇总。例如：`汇总今日其他博主，作者：xxx，内容：xxx`。用户直接输入 Markdown 内容时，也默认视为已处理的内容，按原文汇总并保留正文。

1. 将内容写入当日汇总文件。
2. 必须原样保留用户提供的正文文字。
3. 不总结、不改写、不缩写、不润色、不归纳、不重排正文段落，不新增解释或投资结论。
4. 仅可进行本工作流规定的 Markdown 结构规范化。
5. 涉及公告、业绩、政策、市场数据、价格、CAPEX 等内容时，不主动补充核验结论或风险提示。

### 总结后归档

当用户表达“总结并汇总”“总结后归档”“总结然后归档”“总结后写入今日汇总”，或具有同等明确语义时，视为总结后归档。即使用户输入的是 Markdown 内容，只要明确要求总结，仍按本分支处理。

1. 先基于用户提供的原文提炼总结，再将总结结果写入当日汇总文件。
2. 写入内容为总结后的内容，不保留原文全文。
3. 总结应保留原文的核心观点、论据和结论，不得把研究线索或主观看法表述为既定事实或投资建议。
4. 不生成“共同点与分歧”“当前处理结论”或跨博主综合判断，除非用户明确要求。
5. 涉及公告、业绩、政策、市场数据、价格、CAPEX 等内容时，除非用户明确要求核验，否则仅按原文归纳，不补充外部核验结论。

## 文件结构

每日汇总文件使用以下结构：

```markdown
# YYYY-MM-DD 其他博主公众号汇总

- 来源：其他博主汇总
- 类型：每日公众号
- 博主：[作者A](#作者a)、[作者B](#作者b)

## 作者A

正文

## 作者B

正文
```

## 博主排序

当同一份汇总包含以下博主时，作者正文及顶部博主索引必须按此固定优先级排序：

1. 万种心法
2. 格兰投研
3. 主波浪
4. 宝哥

未列出的博主保留其原始相对顺序，并排在上述四位博主之后。

## Markdown 规范化范围

只允许做以下结构规范化：

1. 日期总标题使用 `#`。
2. 博主/作者标题使用 `##`。
3. 作者下方正文标题整体降一级，从 `###` 开始，避免作者内部标题与作者标题同为 `##`。
4. 更新顶部博主索引，保持作者顺序与正文顺序一致。
5. 规范空行，保证 Markdown 可读。
6. 删除多余 Markdown 横线。

## 横线处理规则

1. 作者标题下方可以保留或添加一个 `---` 作为作者块起始分隔；若标题本身已经清晰，可不加。
2. 文章正文内部尽量不用横线分割。独立成行的 `---`、`----`、`-----` 等，如果只是段落或小节分隔符，应删除，并用空行或标题层级承接。
3. 同一作者正文内部原则上不连续保留多个横线；不同小节之间优先依靠 `###`、`####` 等标题层级和空行区分。
4. 多篇独立文章归在同一作者下时，若没有更清晰的标题层级，可保留少量横线区分文章边界，但不要在每个小节之间机械添加。
5. 不删除 Markdown 表格分隔行，例如 `| --- | --- |`、`|------|------|`。
6. 不删除代码块、引用、原始数据、命令输出中作为内容出现的横线。

删除多余横线属于 Markdown 结构规范化，不视为改写正文文字。在原文汇总场景中，除此之外不得修改用户输入的自然语言内容。
